# Studio de AR Crafts

Seis tipos: `arSite`, `arWorkshop`, `arWorkshopEdition`, `arMaterial`, `arInspiration` y `arFaq`. `arSite` tiene ID singleton fijo y acciones restringidas. Son controles de interfaz; no sustituyen permisos ni validación en la web.

Para practicar toda la landing: [guía editorial de AR Crafts](GUIA-EDITORIAL-AR-CRAFTS.md). La base de ensayo incluye talleres/ediciones, materiales, Inspiración, preguntas e imágenes sustituibles de referencia. Los títulos, introducciones y relatos generales están en **Página → Textos de las secciones**; los datos de cada ficha se editan en su tipo de documento. La identidad y el movimiento permanecen definidos por la web.

Estado comprobado el 2026-10-06: proyecto propio `dbk6sgbx`, dataset privado `ar-crafts-editorial-test`, Studio en `http://127.0.0.1:3334` y preview en `https://ar-crafts-editorial.vercel.app`. La preparación inicial precedía a la creación del proyecto; ahora hay evidencia real de conexión y edición. `localdemo/development` sigue siendo únicamente el scaffold sin credenciales. No importar datos o credenciales de VicaFoods. Sigue el [runbook editorial](AR-CRAFTS-CMS-RUNBOOK.md).

Configurar `SANITY_STUDIO_PROJECT_ID`, `SANITY_STUDIO_DATASET` y `SANITY_STUDIO_PREVIEW_URL`. Presentation usa `/api/draft/enable`, `/api/draft/disable` y Preview URL Secret. La allowlist se reduce al origen exacto; destinos alojados requieren HTTPS. La web configura separadamente `PATO_STUDIO_ORIGIN` y, opcionalmente, `PATO_HOSTED_STUDIO_ORIGIN` para CSP. El perfil aislado propone web `http://127.0.0.1:3001` y Studio `http://127.0.0.1:3334`.

Studio alojado de ensayo: [ar-crafts-editorial-test.sanity.studio](https://ar-crafts-editorial-test.sanity.studio/), conectado al mismo dataset privado. El hostname puede redirigir al Dashboard de Sanity, que contiene el Studio en un iframe. La web permite también el ancestro exacto `https://www.sanity.io` cuando se configura hosting, sin comodines ni cambios a la protección. Hosting manual y acceso del cliente se detallan en el runbook; el cliente no necesita una terminal local. La validación con cuenta cliente propia sigue pendiente. No confundir este ensayo con contenido/lanzamiento comercial definitivo.

Se validan textos obligatorios no vacíos, aprobación con timestamp, fechas con offset, zona exacta Lima e imagen con archivo y alt. Inspiración aprobada requiere fotografía con derechos confirmados. Campos pendientes y estados vacíos se conservan. Titularidad real y control de peso/dimensiones/formatos/animación siguen como gates de ingestión y revisión humana.

Se comprobó sesión de Sanity con GitHub, guardado y publicación desde Studio, borrador en iframe y salida de preview. Vercel protege la web; Presentation usa un bypass exclusivo autorizado por el usuario, almacenado en `sanity-preview-url-secret.vercel-protection-bypass`. Los lectores de ese documento privado pueden utilizar ese acceso; no equivale a permisos de escritura en Sanity. No hay puente live editing/overlays: si aparece el aviso de conexión, usar «Continue anyway» y refrescar después de guardar.

## Entrega del código

Web y Studio comparten la rama fuente `codex/editorial`; la demo en `main` conserva el fixture. Instalar desde la raíz con Node.js 22.12+ y npm 10+: `npm ci`, seguido de `npm run check`. El despliegue Git de la web editorial y la publicación de Studio en Sanity son operaciones separadas. Preparar los perfiles privados desde las plantillas de `config/`, sin versionar valores reales. [ENTREGA.md](../../ENTREGA.md) reúne los pasos reproducibles y el inventario de accesos, titularidad y backup pendiente. Las referencias a `plans/`, `docs/delivery/` o `work/` son evidencia interna local histórica, no dependencias del clon.
